## 언제, 어떤 상태인가요

- **기간**: 2026년 10월 12일 ~ 진행 중 (초급프로젝트 과제1, 마감 10월 31일)
- **상태**: 사이트 배포 완료, 내용 채우기와 점검을 계속하는 중

## 왜 만들었나요

이 사이트로 해결하고 싶었던 목표는 두 가지였습니다.

1. 흩어져 있던 수업 활동과 공부 내용을 **한곳에 모아서 나를 소개하기**
2. 코드를 `main`에 push하면 **GitHub Actions가 자동으로 빌드하고 배포하는 과정**을 직접 만들어 보기

## 내가 맡은 일

개인 과제라서 테마 고르기, 설정 바꾸기, 글 쓰기, 배포, 점검을 모두 직접 했습니다.
막히는 부분은 AI(Claude)에게 원인을 물어보고, 제안받은 방법을 직접 실행하고 결과를 확인했습니다.

## 어떻게 만들었나요

1. **테마 고르기**: 여러 테마를 데모로 비교했습니다. 처음엔 Blowfish를 골랐지만 화면이 복잡하게 느껴져서, 흑백 톤이 차분하고 소개·경력·프로젝트 칸이 처음부터 나뉘어 있는 **Hugo Noir**로 바꿨습니다. 수업에서 받은 준비 스크립트가 빌드를 확인한 테마 목록에 들어 있다는 점도 이유였습니다.
2. **배포 준비**: 테마 ZIP을 풀고 수업 제공 스크립트(`prepare_github_pages.py`)로 배포 설정 파일을 만들었습니다.
3. **첫 push**: 비밀번호로는 push가 막혀서, GitHub CLI(`gh auth login`)로 브라우저 인증을 한 뒤 push했습니다. Actions가 자동으로 돌아가 첫 배포에 성공했습니다.
4. **내 정보로 바꾸기**: `hugo.toml`에서 주소(baseURL), 언어, 이름, GitHub 링크를 바꾸고 테마 예시 내용을 지웠습니다. 바꾼 내용 하나마다 커밋을 하나씩 남겼습니다.
5. **문제 고치기**
   - 메뉴를 눌러도 이동하지 않았습니다. 빌드된 HTML을 열어 보니 메뉴가 없는 페이지를 가리키고 있었고, 홈 화면의 각 칸에 `id`를 붙여 **앵커 링크**로 이동하도록 고쳤습니다.
   - 기술 스택이 화면에 나오지 않았습니다. 테마 코드가 `hugo.toml`의 기술 스택 설정을 읽지 않는 것이 원인이어서, 홈 레이아웃을 복사해 설정을 읽도록 고쳤습니다.
   - 기술 스택 아이콘 줄이 계속 움직여서, 마우스가 없으면 멈출 방법이 없었습니다. "움직임 멈추기" 버튼을 만들고, 기기의 "동작 줄이기" 설정을 켜면 처음부터 멈추도록 했습니다.
6. **화면 크기별 점검**: 390px(휴대폰), 768px(태블릿), 1440px(노트북) 폭에서 사이트를 확인했습니다. 휴대폰에서 글 본문이 화면 절반 폭으로 좁아지는 문제와 태블릿에서 메뉴 줄이 비좁아 줄바꿈되는 문제를 찾아 고쳤습니다.

## 배운 점과 다음 개선

- **배운 점**: 화면만 보고 추측하기보다 **빌드된 결과 파일을 직접 열어 보면** 원인을 빨리 찾을 수 있었습니다. 또 작게 고치고 바로 커밋하니, 문제가 생겼을 때 어느 단계에서 생겼는지 되짚기 쉬웠습니다.
- **아직 남은 점**: 휴대폰 메뉴를 연 상태에서 Tab 키를 누르면 초점이 메뉴 뒤쪽 화면으로 넘어갈 수 있습니다. 또 Safari는 기본 설정에서 Tab 키가 링크를 건너뛰어 키보드 점검 때 설정을 바꿔야 했습니다.
- **다음 개선**: 메뉴가 열리면 초점이 메뉴 안에서만 움직이도록 고치고, 실제 휴대폰으로도 접속해 터치 동작을 다시 확인할 예정입니다.
